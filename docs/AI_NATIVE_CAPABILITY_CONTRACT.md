# LiOS.Pol — AI-native product contract (P1–P5)

**Status:** Product-wide design contract. Phase 1 AI research implementation is a proposed PR until merged and independently verified. Other domains below are future capabilities, not deployed services.

## Principle

LiOS.Pol is an **AI-native political intelligence OS**. AI is a pervasive conversational interface and workflow orchestrator across research, elections, GIS, statistics, psephology, surveys, simulation, policy, legislation, governance, media, field operations, and reporting. It is not a second app layered beside the workbench. Each domain uses **one** model gateway, **one** typed tool registry, authorized domain data, deterministic engines, and a project-linked artifact/provenance system.

`AI explains and coordinates; deterministic tools calculate; citations/evidence support claims; human reviewers approve high-impact actions.`

## Shared tool invocation contract

```text
Question in Chat / Map Lab / Statistics / Research / Teams
  -> single model gateway + context/permission check
  -> planner selects typed domain tool, not another independent LLM backend
  -> tool reads canonical source/project IDs and executes a deterministic owner
  -> tool returns data, version, timestamp, source/evidence IDs, warnings
  -> AI synthesizes within verified evidence / states missing data honestly
  -> artifact saved with the same project/source IDs across chat and workbench
```

Minimum typed tool fields: `project_id`, `actor_scope` (when team mode exists), `capability_id`, `input_schema_version`, `source_ids`, `tool_run_id`, `status`, `output`, `evidence_refs`, `warnings`, `generated_at`. No application may bypass the owning tool to create a duplicate analytic engine.

## AI work by phase

| Phase | AI experience | Data/tool owner | Must be deterministic or verified |
|---|---|---|---|
| **P1** | Conversational evidence-backed research, document ingestion/metadata, source quality diagnostics, cited summaries, explainable artifact generation | `platform/ai`, `platform/search`, `platform/data`, `platform/provenance` | exact source hashes/spans, project scoping, no-evidence state |
| **P2** | NL election comparisons, geospatial questions/AutoMap, statistical method assistance, weighted survey analysis, field form quality checks | `domains/elections`, `platform/gis`, `platform/analytics`, `platform/surveys` | election arithmetic, geometry, sampling/weights, versioned data |
| **P3** | AI policy and legislative research, bill chronology, media narrative summarization, reproducible aggregate forecast/model explanations | `domains/policy`, `domains/legislation`, `domains/media`, `domains/forecasting` | document claims, dates, assumptions, backtest/calibration |
| **P4** | AI supervisor copilot, multilingual field entry, duplicate/incident detection, shift handovers, team status questions and evidence-backed operations briefs | `domains/fieldops`, `platform/auth`, `domains/warroom` | role grants, authoritative tasks, field source classes, audit trail |
| **P5** | Monitored research agents, source-change alerts, bounded scheduled workflows, artifact/report delivery and model regression evaluation | `platform/automation`, `evaluations` | approved triggers, event version, audit IDs, prompt injection tests |

## P1 integrated code contract

- Backend: one FastAPI gateway with `/api/projects/{project_id}/research` supporting `mode=auto|ai|extractive`.
- AI provider adapter: PydanticAI with explicit local Ollama or user-configured HTTPS OpenAI-compatible model. No model is downloaded or contacted merely by starting the app.
- Source-first: project-scoped retrieval produces exact source line IDs/hashes. No source evidence means no speculative political answer.
- Model generation is **invoked in AI mode and auto mode when configured**, with a bounded evidence context. Invalid/missing citation indices reject the output rather than invent an evidence record.
- Artifacts persist `generation_method` and `model_id`; citations refer to the exact original line and source hash.
- Extractive/no-model path is *clearly labeled* as not generated by AI; deterministic data operations remain available without paid keys. Missing models are never advertised as connected.
- Source text is untrusted; no model-driven unapproved network, write, file import, or external contact tools.
- The P1 preview does **not** implement the full source search stack, robust model claim verification, public web retrieval, PDF parsing, election data, GIS, teams, or AI agents for other domains.

## Evaluation gates

- P1: test provenance and exact snippet IDs; no-evidence/no-model; invalid citations rejected; no secret egress; local and optional BYOAI require explicit configuration.
- P2: numeric outputs equal reference fixtures and geospatial errors are surfaced; never let a model silently substitute a value.
- P3: forecast intervals, assumptions and data versions are retained; date/party/bill claims cite primary records.
- P4: negative role tests, revoked/unauthorized requests, offline duplicate receipts and incident audit lineage.
- P5: independent clean install, local-only mode, input prompt injection, model unavailability, licence and regression gates.

**Status standard:** specified ≠ coded ≠ locally tested ≠ CI verified ≠ working with a real model ≠ released.

## Provider trust and consent acceptance (P1)

- Ollama uses loopback endpoints only, no model download or network probe at startup. A user-invoked local probe checks model listing, not inference correctness.
- External BYOAI evidence transmission requires affirmative consent attached to the individual research request; environment variables alone do not permit transfer.
- The API denies non-consenting remote requests before initiating provider traffic. The UI resets consent after each successful generation or project switch.
- Research artifacts record generation method, model ID and validated source references. Valid IDs do not imply claim-level semantic correctness; high-stakes assertions require inspection of original source passages.
- Automated tests must exercise denied remote calls, permitted one-off external generation, opt-in local probing and bad-provider endpoints.
